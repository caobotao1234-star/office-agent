# 飞书图片输入恢复需求

## 目标

恢复用户通过飞书发送图片后由 Agent 识别图片的能力，并在当前模型不支持视觉时优雅降级。

## 用户故事

- 作为用户，我可以给飞书机器人发图片，让支持视觉的模型理解图片并回答。
- 作为用户，我可以发送“图片 + 文字”，支持视觉的模型应同时看到图片和文字。
- 作为用户，如果当前模型是纯文本模型，Agent 应明确告诉我图片识别不支持，但仍继续处理同条消息里的文字。
- 作为维护者，我需要确认旧图片能力是否存在过，以及现在是否被恢复到新架构里。

## 接受标准

- `LLMClient` 能表达 OpenAI vision 格式的多模态消息。
- Provider 能声明当前模型是否支持视觉。
- 飞书 `image` 消息会被下载为 base64 data URL。
- 飞书 `post` 富文本消息会提取文字和图片。
- 非视觉模型收到图片时不报错，不把图片发给 LLM；有文字则继续处理文字，无文字则只提示不支持。
- 单元测试覆盖 QueryEngine 多模态消息构造和 provider 视觉能力判断。

## 非目标

- 不为 DeepSeek V4 强行接图片，因为当前官方 DeepSeek Chat API 未公开图片输入。
- 不做 OCR fallback；后续可以增加独立 Vision/OCR 预处理层。
- 不保存图片到长期会话历史，避免把大体积 base64 写入 session。
