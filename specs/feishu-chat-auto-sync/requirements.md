# 飞书聊天自动同步需求

## 目标

让 Office Agent 在不把每条群聊消息都送进 LLM 的前提下，持续获取有价值的飞书聊天上下文：

- 群聊：机器人被拉进群后，群消息先登记为同步源，后台周期性拉取和抽取有用信息；只有明确唤醒时才进入对话 Agent。
- 私聊：用户可以告诉 Agent 同步自己和某个人的私聊，对方被注册为同步源后，后台周期性拉取聊天记录并沉淀上下文。

## 用户故事

1. 作为用户，我希望把机器人拉进项目群后，Agent 能持续跟进群里的项目状态，但不要每条消息都调用 LLM。
2. 作为用户，我希望只在群里明确 @ 机器人或使用命令时，Agent 才实时回复。
3. 作为用户，我希望告诉 Agent “同步我和张三的私聊”，之后 Agent 能周期性读取这段私聊的新增内容。
4. 作为多用户环境管理员，我希望群聊和私聊同步都绑定到正确用户的 `cliProfile`，不能串用其他用户授权。

## 接受标准

- 群聊消息默认不会触发 `OfficeAgent.handleMessage`，除非满足唤醒条件。
- 群聊消息会为归属用户自动登记 `chat_messages` 同步源。
- 群聊归属按 `appKey + chatId` 记录；已配置用户在群里发消息可绑定该群；单用户 app 可自动归属到唯一配置用户。
- 未归属且无法确定归属用户的群聊消息只记录日志，不创建错误的用户 Agent。
- 已登记群聊/私聊来源可被现有 `FeishuSyncScheduler` 周期性同步。
- 私聊同步使用 `chat_messages --user-id <open_id> --as user`，不要求 bot 加入私聊。
- 所有飞书读取仍必须通过当前用户绑定的 `lark-cli profile`。

## 非目标

- 不实现企业全量消息旁听。
- 不绕过飞书权限模型读取用户无权访问的消息。
- 不对每条群聊消息调用 LLM 总结。
- 不把所有聊天原文直接写入长期记忆；先进入同步源和上下文库，再由抽取逻辑保留有用信息。

## 环境与兼容

- 依赖现有飞书 WebSocket `im.message.receive_v1` 事件。
- 依赖官方 `lark-cli im +chat-messages-list` 和 `im +messages-search` 读能力。
- 后台轮询仍由 `FEISHU_SYNC_INTERVAL_MINUTES` 或用户配置控制；默认关闭。

## 安全约束

- 缺少 `cliProfile` 时不能执行飞书读取。
- 群聊自动归属不能把多用户 app 的群聊随意绑定到某个用户。
- 日志不得打印 appSecret、token 或完整私密内容。

## 可测试性

- 群聊触发策略、群归属存储、同步源参数构造需要单元测试。
- 飞书消息 parser 需要覆盖 `chat_type` 和 mention 判断。
- 不依赖真实飞书 API 或真实 LLM。
