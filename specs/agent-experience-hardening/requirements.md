# Agent 体验与稳定性加固需求

## 目标

把 Office Agent 从“功能可以跑”提升到“能力可追踪、重构不丢能力、飞书入口稳定、长任务可解释、状态文件可靠、用户可自检”的工程状态。

## 用户故事

- 作为用户，我希望之前做过的能力不会在重构中悄悄丢失，并且能通过回放测试发现回归。
- 作为用户，我希望飞书里发文本、富文本、图片、语音、多条连续消息时，Agent 都能稳定处理或明确降级。
- 作为用户，我希望 Agent 调用飞书 CLI 时少猜参数，能基于本地 CLI 帮助缓存和实际版本工作。
- 作为用户，我希望复杂任务做到一半失败时，Agent 能清楚说明完成了什么、失败在哪里，而不是含糊说完成。
- 作为用户，我希望飞书文档、群聊、日历、Base 等变化能被同步并自动更新 Agent 的上下文和知识库。
- 作为用户，我希望本地 JSON 状态文件不容易因为中断写入损坏，损坏时也有备份可查。
- 作为用户，我希望出问题时可以用日志/调试命令快速定位上一轮对话和工具调用。
- 作为用户，我希望能一键检查当前配置、模型能力、飞书 CLI 状态和可用能力。

## 接受标准

- 有一份能力矩阵，覆盖主要输入通道、工具能力、模型能力和测试覆盖状态。
- 回放测试至少覆盖图片降级、飞书 CLI 失败暴露、日程创建、知识捕获、长任务失败说明。
- 飞书事件解析从 bot 主文件中拆出，使用 schema 校验并有单元测试。
- LarkCli 工具具备命令帮助缓存或能力描述缓存，写命令前的引导可复用缓存。
- QueryEngine 或外围运行时能记录一轮操作的工具调用、成功/失败状态和最终完成度。
- Feishu sync 检测到内容变化后，可以自动触发受控知识抽取，并更新 OfficeContext/Memory/Agenda。
- 关键 JSON store 使用原子写入；读到坏文件时备份坏文件并降级为空态。
- 日志具备 turnId/traceId，支持查看最近一轮调试摘要。
- CLI 提供 `oa doctor`，无真实 API key 时也能输出本地配置和缺失项。

## 非目标

- 不恢复旧 Web UI、REST API、旧 FeishuConnector、旧 CalendarTool、旧 EmailTool。
- 不引入复杂 workflow/policy 引擎；保持工具化 Agent，让 LLM 自主调用工具。
- 不在测试中调用真实付费 LLM 或真实飞书 API。
- 不把任何密钥、token、私有路径写进代码或示例。

## 环境与兼容

- Node.js >= 18。
- 保持现有 `npm` 工作流。
- 外部飞书能力继续基于官方 `@larksuite/cli` 和飞书 Node SDK。
- 无 `.env` 或无真实 API key 时，单元测试、typecheck、build、回放测试必须可运行。

## 安全约束

- 日志和调试摘要必须脱敏 user/chat/token/doc 等敏感 ID。
- Lark CLI 不通过 shell 字符串执行，只接受 argv 数组。
- 状态文件备份不能包含额外泄露面；只保留本地同目录备份。

## 可测试性

- 新增模块必须有 mock/fake 测试。
- 飞书入口测试使用 fake event，不依赖真实飞书连接。
- Lark CLI 缓存测试使用 fake runner，不调用真实 CLI。
- Doctor 测试不访问真实网络。
