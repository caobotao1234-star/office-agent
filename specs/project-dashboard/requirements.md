# 项目驾驶舱

## 目标

把 Office Agent 已有的任务、日程、办公上下文和飞书同步源聚合成项目级状态视图。用户问“某项目现在怎么样”“这个项目有什么风险/下一步”时，Agent 应先调用工具读取真实项目状态，再组织回答。

## 用户故事

- 作为用户，我希望一句话询问某个项目，就能看到目标、状态、关键上下文、未完成任务、承诺/截止日期、相关文档和同步源。
- 作为用户，我希望 Agent 不只依赖聊天历史，而是从本地结构化上下文和飞书同步记录中汇总项目状态。
- 作为维护者，我希望项目驾驶舱是只读工具，先稳定输出结构化数据，再交给 LLM 生成自然语言简报。

## 接受标准

- 新增 `ProjectDashboardTool`，支持：
  - `list`：列出已知项目摘要。
  - `get`：按项目名、key、id 或别名生成项目驾驶舱。
- 驾驶舱输出至少包含：
  - 项目基础信息和状态。
  - 最近上下文记录。
  - 未完成任务和高优任务计数。
  - 待办 Agenda、截止日期、承诺、跟进事项。
  - 飞书同步源状态，包括最近同步、变化和错误。
  - 风险/下一步候选项。
- `get` 找不到项目时返回明确失败，并给出可用项目候选。
- 工具为只读，不修改任何任务、日程或上下文数据。
- 新增单元测试和 replay eval，不依赖真实飞书或真实 LLM。

## 非目标

- 不做复杂项目管理 workflow。
- 不自动创建项目、任务或飞书 Base。
- 不直接调用飞书 CLI 拉取最新数据；刷新仍由 `FeishuIngestTool`/同步源负责。
- 不替代 OfficeContextTool，驾驶舱只做聚合和摘要。

## 环境假设

- 项目记录主要存放在 `OfficeContextStore`，类型为 `project`。
- 任务文件仍是 `tasks.json`。
- 飞书关注源仍是 `feishu-sync-sources.json`。
- LLM 根据驾驶舱结构化输出再生成面向用户的简短回答。
